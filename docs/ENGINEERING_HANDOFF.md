## 2. 采集开发副本的最小约定

以下是待实现/验收的要求，不是已通过的软件测试。先确认实际适配器，再改其开发副本；本仓库的证据副本不直接当运行源文件。

- **数据**：每次尝试有唯一编号，关联区域/场景、设备、代码提交、配置与校准版本；保存未经有损可视化替代的彩色图和深度值。掩膜可保存文件或记录可重建规则；单位、无效值、彩深配准方式、原始/对齐网格及内参必须明确。需要原始左右图的方法另存两图与双目标定。
- **时间**：分别记录彩色/深度时间戳、单位、时钟域与所代表事件，以及软件接收时间和配对差值。不能直接比较不同来源的时钟；只有映射有依据才计算差值。配对允许错位按实际运动、目标像素和匹配要求确定，不直接沿用旧 `qc_pass`。
- **运动**：区分指令角度、反馈值、估计位姿和经过核验的相机位姿。写明 `T_base_camera` 的方向：相机光学坐标点映射到区域基座坐标；记录长度单位、轴向、时间关联与标定版本。只有舵机角度时不能填造六自由度实测位姿。
- **新帧与失败**：图像对应的曝光/采集时刻应位于稳定结束后；只有接收时刻时，需验证缓存清理/新帧取得办法并保留限制。无法确认、配对不符、重复缓存、超时或文件未写全时记录失败及原因，不把旧图当成功的新观察。参考复拍是新采集记录；静态回放重访仍按协议复用原记录。
- **保存与可追溯性**：文件写入成功并可重新打开后才标该次保存成功；保留所有失败事件。数据清单记录相对路径、字节数、SHA256、用途和来源观察编号；大文件可放可访问的独立数据位置并登记版本，不把密钥/令牌写入路径。失败计费遵循冻结协议，不能自动补拍而不收费。

[观察表](../experiments/templates/observations.csv)记录运行内的尝试和时序；具体时间戳/位姿等采集元数据用独立 JSON 或设备原始日志保存，并在[文件清单](../experiments/templates/data_manifest.csv)引用。无需把所有原始字段挤进一张 CSV。完整评价数据与未选视图只能由采集/评价端访问。

## 3. 最少需要本机或现场返回的材料

1. 本轮选用的开发板、相机型号和实际输出模式，以及一张相机与支架/云台安装关系图；不能确认的字段写未知。设备本机唯一序列号无需公开。
2. 当前采集适配器、彩深配对、扫描入口的精确版本/路径、配置和脱敏启动命令；依赖先记录现状。旧几何版本仅按报告哈希及对应运行目录定点查一轮，找不到就交回缺失说明，不以调参追平结果。
3. 下一次可访问茶树的时段、允许的非破坏观察/拨叶/移除范围，以及是否有人能按枝条结构核验；未确认则保留未确认。

前三项可以分次交付；未拿到场地安排仍可做离线迁移，未拿到旧代码仍可建立冻结后的新实现。首次自然茶树开发采集的完整交回清单见[工作表](../experiments/templates/development_session.md)。

## 4. 本轮避免新增的无依据负担

无需先购买新板卡/相机、搭完整采摘机器人、训练新网络或统一四关键点/等级模型。也不因旧室内示例正常便跳过实际茶树成像检查。先确认已有设备及可达观察几何；若光心位移和视野不足，再用测量结果决定需要怎样的运动改动。定量融合可以采用有依据的独立位姿量测，不强制指定某一种云台外参求解或定位算法。
