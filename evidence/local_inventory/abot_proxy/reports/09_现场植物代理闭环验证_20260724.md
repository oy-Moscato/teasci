# ABOT-X4 现场植物代理闭环验证（2026-07-24）

> 结论：**感知接口闭环成立，但茶叶识别、定位稳定性和可达性均未通过采摘安全门；本轮正确终态为拒绝执行。**
>
> 本报告只证明 `RGB/人工审计 bbox → 注册点云 → /target_point → 可达性判定` 能在真机运行，不证明画面植物是茶树，也不证明机械臂可采。

## 2. 环境观测

- RGB 显示教学楼庭院和大面积低矮阔叶地被/灌丛；俯视后植物占据大部分画面。
- 单帧形态不足以鉴定物种，且画面没有可确认的“一芽一叶/一芽二叶”茶芽结构，因此不得标为茶树或茶芽。
- 户外强光下 Gemini 深度孔洞明显：初始帧 `0.15–3.0 m` 有效像素率约 `9.36%`，有效深度中位数约 `2.106 m`。

## 3. 识别与三维定位

### 3.1 真实模型结果

现有 `yolov5n` TensorRT FP16 COCO 模型运行超过 480 帧，持续 `detections=0`。COCO 类别集不包含茶芽/茶叶，所以这不是视觉链故障，也不能用其他 COCO 类别代替茶叶识别成功。

### 3.2 植物代理接口测试

为只验证接口，人工审计俯视图后发布：

- `Class=plant_proxy`
- `probability=0.99` 仅表示测试消息固定值，不是模型置信度
- bbox：`(xmin=250, ymin=280, xmax=470, ymax=475)`
- `image_header` 逐帧取自真实 `/camera/rgb/image_raw`
- 定位器：`source_mode=yolo`、`geometry_input=point_cloud`

12 次输入得到 6 个 `/target_point`，全部为有限值，且 `frame_id=camera_rgb_optical_frame`。原始输出位于 `artifacts/现场植物代理闭环_20260724/target_points_small.yaml`（未纳入本证据包）。

| 指标 | 结果 |
|---|---:|
| 有效定位率 | `6/12 = 50%` |
| `x` 中位数 | `0.127 m` |
| `y` 中位数 | `0.151 m` |
| `z` 中位数 | `0.808 m` |
| 相机到点欧氏距离中位数 | `0.841 m` |
| 距离范围 | `0.800–1.019 m` |
| 距离 P95 | `0.991 m` |
| `≤0.55 m` 样本 | `0/6` |

定位器对无结果帧给出 `No supported depth cluster` 或 `No geometry frame within 0.100 s`，符合失败关闭行为。50% 有效率远低于既定 `≥90%` 门槛，且静态目标点离散明显，不能进入外参或机械臂阶段。

## 4. 闭环判定

| 环节 | 状态 | 说明 |
|---|---|---|
| RGB 环境捕捉 | PASS | 30 Hz，云台俯视获得植物主体画面 |
| LiDAR 环境捕捉 | PASS（raw） | `/scan_raw` 10 Hz；过滤 scan 因 TF 缺失不可用 |
| 茶叶/茶芽识别 | BLOCKED | 当前只有 COCO 权重；现场植物物种未确认 |
| 2D→3D 接口 | PILOT PASS | 人工 `plant_proxy` bbox 成功产生 `PointStamped` |
| 定位有效率 | FAIL | `50% < 90%` |
| 物理三维精度 | PENDING | 未使用 0.3/0.5/0.8 m 标定物，不得声称精度通过 |
| 可达性 | FAIL | 最近约 `0.800 m > 0.55 m` |
| 采摘执行 | NOT RUN | 安全门拒绝；未启动机械臂、夹爪或底盘 |

因此完整工作流的验证结果是：**发现植物场景 → 无茶芽模型证据 → 代理框可完成三维定位 → 定位率与可达性检查失败 → 拒绝采摘。** 这证明安全门生效，不是采摘成功。

## 5. 下一次允许进入真实采摘前的硬条件

1. 使用经标注与独立验证的茶芽 `det+kp+seg` 权重，禁止继续用 COCO 或人工框冒充识别。
2. 现场必须出现可确认且已授权测试的茶树/茶芽，而不是任意校园植物。
3. 完成 0.3/0.5/0.8 m 米制精度门，并使有效定位率达到 `≥90%`。
4. 目标位于机械臂标定后的真实工作空间，且相机到臂外参通过验证。
5. oy 现场确认急停、清场和机械臂运动授权后，才可单独进入 plan-only，再决定是否实动。
