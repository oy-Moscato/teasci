# ABOT-X4 现场代理茎 3D 方向闭环（2026-07-24）

> 结论：**现场植物作为茶芽茎代理物的 3D 主轴实验闭环已跑通。29/30 帧通过几何与稳定性门，输出相机坐标系单位轴向；目标距相机最近 `0.780 m`，超过 `0.55 m` 可达门，因此闭环最终安全拒绝运动。**
>
> 这是 `school_shrub_proxy` 工程验证，不是茶树物种鉴定、自动茶芽识别结果或机械臂采摘成功。

## 1. 实验合同

方向合同沿用项目冻结的 4kp 语义：

```text
KP1 = 代理茎基部
KP2/KP3 = 沿代理枝轴的中间审计点
KP4 = 代理茎尖端侧
positive axis = unit(KP1 -> KP4)
frame = camera_rgb_optical_frame
```

本轮现场没有可用茶芽 4kp 权重，因此 2D 关键点由人工在真实 RGB 上审计，不声称为模型检测。随后所有深度选择、3D 拟合、多帧稳定性和安全判定均由程序自动完成。

审计像素点：`[(140,400), (170,390), (205,385), (240,380)]`。

原件中的代理茎轴标注图位于 `artifacts/现场代理茎3D方向_20260724/proxy_stem_axis_annotated.png`（未纳入本证据包）。

## 2. 处理链

```text
Gemini RGB + registered PointCloud2
  -> 4 个有序 2D 代理茎关键点
  -> 每点圆形邻域投影
  -> 20 mm 深度分箱，取最近且有足够支持的深度簇
  -> 各簇 XYZ 中位数
  -> RANSAC/直线内点 + SVD/PCA 精化
  -> 按 KP1->KP4 消除轴向正负二义性
  -> 单帧几何门 + 30 帧角度稳定门
  -> /proxy_stem/origin + /proxy_stem/axis
  -> 0.55 m 可达性门
```

ROS 输出：

| Topic | Type | 语义 |
|---|---|---|
| `/proxy_stem/origin` | `geometry_msgs/PointStamped` | 3D 轴内点中心 |
| `/proxy_stem/axis` | `geometry_msgs/Vector3Stamped` | KP1 指向 KP4 的单位方向 |

两个 topic 均为 `camera_rgb_optical_frame`，只表达几何证据，不连接任何运动消费者。

REJECT_OUT_OF_REACH

## 5. 安全与边界

- 云台从中位 `(90,90)` 调到 `(90,60)` 俯视，实验后恢复 `(90,90)`。
- rosserial 将 `/cmd_vel` 重映射到 `/safety_disabled/cmd_vel`；该 topic 无 publisher，原 `/cmd_vel` 不存在。
- 实验前后抽查 `/raw_vel` 均为零。
- 未启动 `bringup`、LiDAR、导航、xArm、夹爪、`ZachLab_grasp` 或抓取状态机。
- 收尾后 camera、隔离 rosserial 和 ROS master 均已退出；可用内存约 `2658 MiB`。

## 6. 能证明与不能证明的内容

本轮能证明：

1. ABOT Gemini 注册点云能够支撑现场代理枝轴的多点 3D 定位。
2. `KP1→KP4` 主轴方向可稳定输出为 ROS `Vector3Stamped`。
3. 几何、稳定性和可达性门能形成失败关闭闭环。

本轮不能证明：

1. 画面植物是茶树，或代理枝轴等价于嫩茶芽茎的力学结构。
2. 2D 关键点由茶芽模型自动识别；本轮是人工审计输入。
3. `10.50 mm` 直线拟合残差等于绝对三维精度；0.3/0.5/0.8 m 物理标定门仍未完成。
4. 当前点位可由 xArm 到达，或适合执行 P1–P5 仿人拧掰。
